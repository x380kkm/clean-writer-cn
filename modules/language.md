## 执行顺序

1. language revision 是 lead writer 的成稿阶段. 它使用用户任务, 当前文本, 核验结果和必要限定.
2. lead writer 可以在修订中调整选材, 结构和详细程度. 调整需要新事实时先向 research support 提问, 不从核验记录或常识补写.
3. 跳过引文, 代码, 数字, 专有名称和本文件没有列出等义替换的术语.
4. 按本文件列出的词语或短语检查其余正文.
5. 发现表中条目后按对应规则直接修改.
6. 只使用当前文本和核验结果中已有的信息完成修改.
7. 修改后确认事实关系, 范围和必要限定没有被扩大或改变.
8. 写作样本只用于确定指代和信息归属, 不用于推断作者人格, 经历或观点.

已经选入正文的标准技术缩略语属于术语, 保持原样. 团队内部简写按下文规则处理.

## 句式

以下句式出现后直接改成平直陈述:

本文件中的删除, 合并和改序遵守 `SKILL.md` 规定的事实, 范围, 语气和强度. 重复本身承载这些内容时, 用平直文字保留相同内容和强度.

判断者只在材料明示时写出. 原文未明示时保持无主判断, 不推断主体.

| 句式 | 修改 |
|---|---|
| 不是 X, 而是 Y; 不只是 X, 而是 Y | 分别说明 X, Y 和两者的差异. |
| 两面对称陈述, 包括一方面 X, 另一方面 Y | 分别说明已有证据, 成本, 限制或条件. 不补写缺失内容, 不删除真实权衡, 不替作者下结论, 不把矛盾感受改成单一立场. |
| 让步部分不改变后续判断条件的句子 | 把已有的限制和后续判断分别直述. 保持真实限制和决策条件. |
| 从 X 到 Y | 保留 X, Y, 方向和材料唯一确定的关系. 关系不能唯一确定时不补写关系类型. |
| 无论 X 还是 Y | 写明范围和各项条件. |
| 真正重要的是 X; 问题的核心是 X; 关键是 X | 保留材料明示的判断者, X 的原有适用范围, 优先级和评价强度. 只删除不承载这些内容的宣告句式. |
| 我意识到的是 X | 写明认识者和原有认识, 只删除不承载认识过程的句式包装. |
| 模式如下 | 删除只提示下文的句子, 直接写材料已有的模式. |
| 这体现了 X; 这彰显了 X; 这证明了 X | 写出材料已有的事实和结论关系, 并保持原有证据强度. |
| 这为 X 奠定了基础 | 保留材料明示的判断者, 适用范围, 材料已有的条件, 条件与 X 的原有关联强度, 以及 X 的原有预期或实际状态. |
| 三项排比 | 分别写明三项内容. 合并重复项时保留已有事实和强度. |
| 只重复已有命题的对称句 | 直接写已有的因果, 后果或决定, 并保留已有事实和强度. |
| 材料包含其他选项却只列两个选项 | 写明材料已有的选项, 范围和限制. |

连续句子使用相同开头时, 按本节的事实和范围要求合并重复部分. "先 X 再 Y" 承载事实顺序时保留先后关系. 操作步骤可以改成编号步骤, 其他内容改成两句直接陈述.

其他对比句也分别写明对比对象, 比较维度和材料已有的差异, 并保持比较基准不变.

## 连接词

连接词必须写明真实关系:

| 原词 | 修改 |
|---|---|
| 此外 | 保留原有并列或递进关系, 把新增事实并入相应句子. |
| 然而 | 保留原有转折或对比关系, 直接写两项事实及其关系. |
| 因此 | 保留原有推论或因果强度, 直接写前提和结论. |
| 与此同时 | 材料确认同时发生时写明时间关系; 否则改用材料已有的关系. |
| 总的来说 | 保留材料明示的判断者, 总体范围和原有强调程度. 只删除不承载这些内容的包装. |

连接词没有表达真实关系时直接删除. 连续多句都以连接词开头时, 合并重复关系.

## 句段节奏

- 连续多句长度和结构接近时, 拆分复杂句并按本节的事实和范围要求合并重复句.
- 不套用固定字数, 句长或段落长度.
- 不插入无信息短句来改变节奏.
- 不把所有长句拆成短句, 也不把所有短句合成长句.
- 连续段落反复用"这里", "这些", "这说明"或"这意味着"概括前文时, 逐项检查它是否增加判断或限定. 只复述前文时删除; 增加条件或后果时, 把该条件或后果放到它实际影响的判断附近.
- 一句话或一段同时罗列外部事件, 对象类别, 状态属性和代码标识时, 先按判断依据分组. 正文保留压缩关系和必要限定, 不把不同层次的内容压成一个长清单.

## 修辞和写法偏离

比喻, 拟人, 反讽, 口号和俏皮表达不自动使文字自然. 先使用当前文本中的内容关系和必要限定. 表达承担材料已有的比较, 情绪, 评价或反讽作用时保留这些内容和强度; 只改变气氛或节奏时, 改成材料已有的对象, 动作, 条件或结果.

标题或局部段落突然使用与上下文不同的写法时, 检查后文是否完成它产生的预期. 任务或材料没有选择这项作用时, 改回与当前文体相称的字面表达. 软件和系统确实执行的读取, 写入, 重试, 停止和恢复不是拟人. 用户明确要求文学表达, 反讽或仿作时保留有意偏离, 不把它改成技术说明.

## 翻译腔和冗长表达

| 原表达 | 修改 |
|---|---|
| 对 X 进行处理 | 处理 X. |
| 基于 X 来实现 Y | 用 X 实现 Y, 或直接说明 X 如何产生 Y. |
| 在 X 的背景下 | 直接说明背景及其影响. |
| 具有做 X 的能力 | 能做 X. |
| 从 X 到 Y 的旅程 | 写明 X, Y 和材料唯一确定的空间, 时间, 顺序, 状态或变化关系. 关系不能唯一确定时保留 X 到 Y 的方向, 不补写关系类型. |
| 由于 X 这一事实 | 因为 X. |
| 在当前这个时间点 | 现在. |
| 在 X 的过程中 | 表达时间范围时改为在 X 时. 不表达时间范围且不承载其他内容时删除. |
| 出于 X 的目的 | 为了 X. |
| 关于 X 这一方面 | 关于 X, 或直接进入内容. |
| 需要注意的是, 值得注意的是 | 保留材料明示的判断者, 原有优先级和强调程度. 判断者未明示时保持无主判断. 只删除不承载这些内容的包装. |
| 换句话说 | 合并重复命题并保留新增信息. 重复承载 `SKILL.md` 规定的事实或适用范围时用文字保留相同内容和强度. |

多个修饰成分连续放在中心词前时, 拆成主句和补充句. 修改后核对因果, 转折, 条件和不确定程度.

## 行话, 简写和口语

业务行话包括: 赋能, 助力, 深耕, 布局, 聚焦, 打造, 构建, 抓手, 闭环, 底层逻辑, 顶层设计, 颗粒度, 链路, 全链路, 生态, 降本增效, 范式, 用户心智, 打通, 沉淀, 破圈, 引领, 维度, 比喻义的拥抱和链接.

删除行话词, 用材料中已有的对象, 动作, 结果, 指标或时间直接陈述. 替换后不要改变是谁作出评价, 也不要加强或减弱评价. 材料已经准确说明技术术语时, 不改变它的含义.

不要只检查词表. 只有目标读者需要识别某个名称时, 正文才保留来源中的阶段名, 临时分类名或内部名称. 其他情况直接说明谁处理什么, 采用什么条件, 产生什么结果. 连续使用抽象名词, 或用一个抽象名称解释另一个抽象名称时, 改写成读者可以按顺序理解的对象和动作. 例如, 把 "聚焦更新" 写成 "只更新指定文件", 把 "围栏代码" 写成 "Markdown 代码块", 把 "用可观察的结构边界确定符号范围" 写成 "按各语言的语法判断定义从哪里开始, 在哪里结束".

这项修改适用于正文, 标题, 列表标签, 表头, 图中节点, 箭头文字和图注. 图示需要短标签时也要保留具体对象和动作, 不能退回内部阶段名或宽泛分类词.

材料已经解释领域术语时, 只保留读者理解正文所需的说明, 不改变术语含义. 读者需要准确识别的术语名称, 参数, 单位, 命令, 变量, 产品名和协议名保持原样. 需要保留名称时, 只保留正文实际使用的名称; 不必因此保留输入中的整句话. 前文已经省略读者不需要识别或使用的名称和位置时, 语言修订不要把它们补回.

正文只需要说明对象和结果时, 不保留成员名, 类型名, 内部资源格式和变量名. 正文需要解释设计和机制, 但读者不需要识别代码名称时, 省略这些名称, 用材料能够确定的普通名称说明这些对象之间的关系. 读者同时需要识别代码名称时, 保留原名并在首次出现处说明含义. 公共接口和用户可见设置只有在读者需要识别或使用它, 或文章讨论的正是这个名称时才保持原名. 精确格式只有在它改变当前判断或取舍时才保留.

生活用语和团队口语包括: 说白了, 捋一捋, 盘一盘, 聊一聊, 这玩意, 搞定, 人肉处理, 老功能, 事情是这样的, 老实说, 这块有问题, 接不住, 扛不住, 落地还是粗的, 落不了地, 事情变味了, 不太对, 有点怪, 吃掉复杂度和服务吃满内存.

把这些表达改成说明同一对象, 动作, 状态和判断依据的普通话书面表达. 不补写群体背景, 经历或说话人态度.

正文出现本节列出的完整词语时, 按本节规则修改. 引文, 代码或专有名称中的相同文字不修改. 术语中的词语只有在本文件给出含义相同的替换词时才修改. 未列出的生活用语, 团队口语, 俚语和圈内表达只有在当前材料能够确定含义和普通话书面说法时才修改. 材料不能确定含义时不自行解释. 同一对象已有普通话书面说法时, 统一使用该说法, 并保留举例目的, 情绪和说话人归属.

社交内容中的亲密和情绪表达只删除不承载称呼, 情绪或经历的包装. 保留感受者, 对象, 原有强度, 称呼, 经历及其归属.

API, HTTP, PDF, CPU, GPU, KPI 和 OKR 等正文需要的标准缩略语保持原样. 上下文能够确定团队内部简写的完整含义, 且不展开会影响理解时, 首次出现写成 "完整含义 (简写)"; 后文使用简写. 上下文不能确定简写含义时, 保留原文, 不自行展开. 中英混用时把普通英文词改成准确中文, 例如把 `ticket` 改成工单; 正文需要的代码名称, 命令和产品名保持原名.

同一对象使用同一准确名称. 不为避免重复而轮换公司, 企业和组织, 或开发者, 工程师和从业者. 概念确实变化时才改用其他名称.

## 主观表达和信息省略

| 类别 | 检查对象 | 修改 |
|---|---|---|
| 作者立场 | 我认为, 我觉得, 在我看来, 我倾向于, 我更看重 | 保留判断者, 判断对象和原有强度. |
| 证据判断 | 不难看出, 显而易见, 毋庸置疑, 不可否认的是, 由此可见 | 把结论改成相同确定程度的直接陈述. 材料已有依据时保留结论和依据; 材料没有依据时, 不补写依据, 也不另加材料缺少依据的说明. |
| 情绪和偏好 | 我喜欢, 我反感, 令人振奋, 令人失望, 遗憾的是 | 保留材料已有的感受者, 对象, 原有强度和原因; 只删除不承载情绪的包装. |
| 人际评价 | 优秀, 糟糕, 可靠, 不负责任, 值得信赖 | 保留材料已有的评价者, 对象和原有强度. 材料已有具体行为和结果时保留; 材料没有提供时不补写. 保持原有礼貌程度, 分歧和冲突强度. |
| 修辞性断言 | 事实上, 实际上, 本质上, 真正的, 核心, 关键在于, 所有人都知道 | 保留材料已有的判断者, 原有命题, 适用范围和强调程度. 只删除不承载这些内容的反问或格言句式. |
| 认识限定 | 可以说, 某种意义上, 从某种角度来看, 在很多情况下, 往往, 通常, 可能, 或许, 大约, 我不确定 | 保持原有不确定程度并改写句式. 材料已有明确的证据范围, 概率或条件时写明; 材料没有提供时不补写. |

判断者, 感受者, 评价者和建议者只在材料明示时写出. 原文未明示时保持原有无主表达, 不推断主体.

表达省略对象, 判断维度, 比较基准或关系时, 补出当前句, 前后文和关联材料中唯一确定的信息. "这个不行", "太重", "不够稳", "更快", "更好" 和 "更省" 都要写明对象及判断依据.

- 领域内省略补全材料唯一确定的术语定义, 指代和领域关系.
- 对话省略补全上一轮唯一确定的指代和判断.
- 材料不能唯一确定时保持未知, 不补造内容.

## 具体性, 归因和宣传

本节只使用材料已经提供的名称, 数量, 指标, 行为, 结果和来源. 材料没有提供所需字段时, 保留原命题和强度, 不补造字段, 不添加缺失说明.

| 问题 | 修改 |
|---|---|
| 性能显著提升 | 改为 "性能有显著提升". 保留 "性能", "显著" 和 "提升" 的含义及材料已有的指标和测试条件; 不补写指标或缺失说明. |
| 许多团队已经采用 | 改为 "已经有许多团队采用". 保留 "许多", "已经" 和 "采用" 的数量, 状态与关系; 不补写数量或缺失说明. |
| 用户体验得到优化 | 改为 "用户体验经过优化". 保留 "用户体验" 和 "优化" 的对象, 行为与状态; 不补写依据或缺失说明. |
| 项目取得明显进展 | 改为 "项目有明显进展". 材料已有里程碑, 完成项或日期时保留; 没有时不补写依据或缺失说明. |
| 专家认为, 研究显示, 业内普遍认为 | 保留原有归因, 结论范围以及材料已有的来源和时间. 不补写未知来源或缺失说明. |
| 隐藏关键行为者的被动句 | 材料已有行为者时写明行为者. 行为者未知时保持原有无主句或被动句, 不补造主体. |

材料唯一确定责任主体时补出责任主体. 材料不能确定时保持未知, 不补造主体.
